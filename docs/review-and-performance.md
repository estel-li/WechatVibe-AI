# Tauri 版代码 review 与优化

日期：2026-10-07。维护者：[estel-li](https://github.com/estel-li)。项目：[WechatVibe-tauri2](https://github.com/estel-li/WechatVibe-tauri2)。首次验证时曾使用本机 Git 署名“老李”；该历史署名仍可见于早期截图和验证 JSON，当前关于页已按维护者要求更新。

本次检查覆盖 Rust/Node 桌面生命周期与 IPC、前端消息及标签刷新、会话和模型来源隔离、剪贴板、设置与更新弹窗，以及源码打包清单。微信读取、模型提示词、画像统计和现有业务接口保持原有语义。

## 已修复的问题

| 优先级 | 问题及影响 | 修改与验证 |
| --- | --- | --- |
| P1 | 被拦截的外部导航仍触发 beforeunload，注销原生事件，随后下载、更新和错误反馈失联。 | 改在实际 pagehide 时释放订阅。真实 WebView2 先执行被拒绝的导航，再终止合成 worker，验证错误事件仍能到达界面。 |
| P1 | Node worker 异常退出后，Python 服务可能继续占用端口，后续 RPC 缺少明确的退出状态。 | 同时检测进程退出和管道关闭，结束待处理请求。正常退出回退到原 launcher，按 PID 创建时间、安装身份和控制令牌核对所有权。测试分别证明故障清理、启动失败保留复用服务、更新交接不触碰服务。 |
| P2 | 80 条消息滚动窗口每新增一条就重建整页消息节点和头像。 | 按消息 ID、完整消息内容及账号/头像上下文复用节点。真实 DOM 验证保留 79/80 行，新增和修正各创建一行；标签使用既有独立更新逻辑。 |
| P2 | 重复创建日期格式化器。 | 复用 Intl.DateTimeFormat；边界和中文 locale 输出测试通过。 |
| P2 | 快速重复复制、等待时继续编辑，可能并发操作或在浏览器回退时复制错误内容。 | 显示复制中状态并串行处理，临时文本框只复制该次操作捕获的草稿，完成后恢复焦点及按钮。 |
| P2 | 设置导航不支持完整键盘操作；弹窗未约束和恢复焦点。 | 按钮、ARIA tabs、方向键、Tab 循环、Escape 和嵌套焦点恢复；关闭按钮定位到卡片内。 |
| P2 | 大字号下弹窗可能超出小窗口。 | 按缩放后的可用视口计算尺寸，长内容内部滚动；实测 720×520 视口与 150% 缩放。 |
| P3 | 调整尺寸产生重复的最大化状态通知和前端查询。 | Rust 只在状态改变时通知，移除前端重复 resize 查询。 |

## 性能证据与范围

本机 Node v24.18.0，2,000 个有效时间戳、三轮中位数：原实现 82.13 ms，新实现 3.00 ms，约 27.35 倍，locale 输出一致。实际 WebView 滚动窗口只创建 1/80 个消息节点，测量范围为日期格式化及 DOM 渲染，模型推理使用原有流程。

SQLite 另做了 300 条合成结果的对比：逐次开关连接时，DELETE/FULL 约 2.851 s，WAL/FULL 约 4.143 s，未采用这一变更。保留原有持久化、事务和账号删除流程。
