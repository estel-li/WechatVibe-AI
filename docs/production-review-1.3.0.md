# 1.3.0 生产审查记录

日期：2026-10-07。审查与改进对象为本仓库的 Tauri 2 主项目；工作目录旁的 Electron 副本是迁移前参考，不参与此版发布。

## 覆盖范围

| 领域 | 审查重点 |
| --- | --- |
| UI 与状态 | 会话列表、未读、消息加载与滚动、历史搜索、设置、四种外观、缩放、弹窗焦点、键盘可达性、错误恢复。 |
| AI 与任务 | 提示词与模型协议、长历史分段、任务取消、来源/账号/会话隔离、结果渲染、用量信息、复制与导出。 |
| 服务与存储 | 本机 HTTP 权限和 body 边界、任务线程和生命周期、缓存/结果 SQLite、历史分页、账号校验、异常信息脱敏。 |
| 原生读取 | 只读数据库、消息身份与去重、重复历史、压缩消息、快照写入、读取异常。 |
| 桌面与更新 | Rust / Node 生命周期、主窗口 IPC 权限、剪贴板、用户选择文件保存、签名更新和数据保留。 |
| 发布与依赖 | 锁文件、暂存清单、隔离导入、安装版/绿色版一致性、版本与下载链接、生产依赖审计、自动回归。 |

## 主要发现与处置

| 问题 | 改进与依据 |
| --- | --- |
| 会话区不能完整使用键盘，历史位置回到尾部困难 | 可聚焦会话按钮、方向键与 Home / End，未读筛选和返回最新入口。 |
| 会话未读逐行解析 localStorage，搜索翻页重复联网 | 渲染周期复用读取结果、查询范围内的分页缓存；命中高亮和失败重试。 |
| 会话区 HTML 缺少闭合标签 | 修复结构，并以真实 WebView DOM 与小窗口布局验证。 |
| 720×520 与 150% 缩放会裁掉复制草稿按钮 | 允许编辑区正确缩放，压缩小屏模型栏和工具区，保留消息区域及全部操作按钮可达；真实 WebView 测量验证。 |
| 助手不同模式结果丢失、相同状态频繁重绘 | 总结/回复按会话保留、减少轮询重绘；让语气和导出直接服务日常操作。 |
| Windows 大 POST 未读取 body 即关闭导致连接重置 | 有界读取/拒绝过程、真实 HTTP 与 raw socket 测试覆盖长度冲突及异常传输。 |
| 清除账号预备步骤异常可使服务一直返回 503 | 在停止本地 worker 和接触数据之前的失败阶段恢复 closing 状态，让操作可以重试；原有账号删除事务保留。 |
| 畸形 Node JSONL 响应可使读线程退出并长期等待 | 校验 envelope 类型、响应 ID 和错误结构；合成进程验证畸形消息后仍能接收正常响应。 |
| 原生去重共享状态、重复行可能使分页结束 | 去重按会话隔离，继续扫描重复页并保持分页边界。 |
| 压缩消息缺少展开上限 | 限制压缩和输出大小，避免损坏或异常数据库内容持续分配内存。 |
| 快照固定临时文件名可能并发冲突 | 每次写入独立临时文件，完成后替换；失败清理该次文件。 |
| 流式模型响应缺少总量边界、兼容 JSON 可直接无界读取 | 流量限制保留早期 delta，超限取消 body；兼容 JSON 复用有界读取。新增验证确认超限仅一次调用。 |
| 导出缺少桌面保存能力 | 受主窗口权限约束的原生保存对话框；UTF-8 写入，合法扩展名校验、中文名处理、原子替换，拒绝和失败不破坏已有文件。 |
| README 当前版本陈旧，发布文件可能分叉 | 统一 1.3.0，自动核对 package/Cargo/Tauri/锁文件/README/说明，加入 Windows CI。 |

## 保留的边界

消息身份中可变 `server_id` 可能在发送回执变化后影响缓存键。直接更换历史 ID 会触发已有分析缓存迁移或重算，本轮保留兼容语义，避免把消息 ID 调整夹带为无提示的数据迁移。后续若实现跨重启收藏，需使用稳定历史游标并规划迁移。

模型分析准确率、真实微信版本兼容性和用户机器 GPU 性能无法由合成 fixture 证明。本轮的测试结论限于程序行为、边界、数据隔离、界面操作与打包一致性。竞品中已存在的自动发送、远程记忆等能力不改变本工具当前人工操作及本机只读定位。

## 验证入口

```powershell
npm test
cargo clippy --locked --manifest-path src-tauri/Cargo.toml -- -D warnings
npm audit --omit=dev --registry=https://registry.npmjs.org
npm run build:portable
npm run build:installer
```

构建后使用 `verify-tauri-ui.py`、`verify-ai-assistant.py`、`verify-analysis-models.py` 检查原生桌面、真实 HTTP / Python / Node / SDK fixture 链路，再从安装器提取相同载荷验证。发行验证记录包含实际检查结果、文件大小与哈希，不把尚未执行的检查记作通过。
