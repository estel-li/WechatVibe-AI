# WechatVibe 1.2.3 发布说明

> 以下保留原 Electron 项目的历史发行说明。Tauri 2 构建、目录布局及更新包约定以本目录 README.md 和 MIGRATION.md 为准；这些旧下载包不用于 Tauri 2 客户端升级。

本版让 API 人物画像共用本地 Laya 的判断条件、累计与评分规则，同时保留 API 根据上下文容量整批分析聊天的能力。修复画像切换、缓存清除和流式标签对应问题，增加手动聊天记录路径与会话添加入口，并使用新的单气泡笑脸图标。

Laya 继续作为独立的 `WechatVibe-Laya-model-v1.zip` 提供，沿用现有下载入口与模型文件。已有模型无需重新下载；只使用 API 时无需安装本地模型。本版交付形式仍为标准应用包加独立模型包。

## 画像有什么变化

API 仍然读取所选会话的上下文：容量足够时一次判断，超出时自动分批。变化在于模型回答统一的行为判断问题，程序根据保存的结果累计并计算最终好感度、MBTI、互动风格、词频及摘要，使用与本地 Laya 相同的评分代码。之前生成的画像不再被反复作为新判断的事实输入。

界面继续使用原有的画像卡片。新的 API 结果采用相同的证据条件，未知维度保持未确定；群整体不显示个人 MBTI 和好感度，具体成员独立累计。消息达到 100 条只满足 MBTI 的文本数量门槛，不代表每一轴都会得到确定结论。

从 1 条有效目标文本即可开始累计。结果与已处理进度一起保存，失败后继续未完成内容；没有新文本时不会重复调用模型。切换会话或重新启动时先显示已保存画像，后台状态更新不再反复重建整张页面。

## 老用户升级后需要做什么

1. 1.2.0、1.2.1、1.2.2 用户可在「设置 → 关于 → 当前版本」检查更新。使用标准应用包的原有数据、配置与独立模型继续保留。
2. **旧 API 画像会先保留显示**。在对应会话点击「更新画像」，才按新规则重新分析；重建期间会注明正在显示旧画像。无需先清除整份模型缓存。
3. API 画像的上下文设置至少为 **12288 tokens**。请填写模型服务实际支持的容量；低于门槛会阻止提交并说明原因，超过服务商实际支持范围会返回相应错误。
4. 本地 Laya、各 API 模型、不同账号和群成员的结果仍分别保存。清除某个模型的分析缓存会清除该来源的相关分析结果，请按设置里的来源名称操作。

1.0.4 的旧更新器仍不支持新版标准包，请手动下载。完全退出旧版后覆盖应用文件，保留 `resources/client/.local` 和 `resources/client/.models`，不要先删除旧软件目录。

## 其他改进与修复

- **Windows 启动兼容**：避免安装目录对应的服务端口恰好被系统保留而无法启动；自动选择并保存可用端口，保持重启、停止与更新流程一致。
- **消息标签对应更可靠**：API 返回的短编号会还原到原消息，兼容乱序和逐步返回；缺失、未知或冲突结果不会冒充成功。失败时清除未确认的流式预览，保留已经保存的标签。
- **画像缓存清除生效**：在聊天页打开设置清除当前模型缓存后，回到画像页不会再恢复已清除内容；旧请求迟到也不能复活旧快照。
- **手动选择聊天记录路径**：在「设置 → 通用设置 → 聊天记录路径」选择 `xwechat_files` 或账号目录，也可恢复自动发现。软件仍按当前登录账号完成校验。
- **添加会话更方便**：左侧搜索框旁的「＋」长期保留；会话目录已就绪时即可管理列表，无需等待全部消息加载。
- **新图标**：启动、关于、更新界面和 Windows 应用图标统一为单气泡笑脸，保留透明外缘。
- **启动诊断**：将 `WechatVibe-diagnose.bat` 放到 EXE 所在目录运行，生成用于排查文件、依赖和启动错误的报告。工具不启动应用或模型，不读取聊天数据库、API Key，也不会自动上传。详见[启动诊断说明](../startup-diagnostics.md)。

本轮功能已由维护者完成实端验收。相关回归覆盖判断结果累计、断点、来源隔离、缓存清除、流式标签和桌面入口；这些检查不代表所有模型会得出相同结论，也不构成人格准确率指标。

## 发布校验

- Windows 标准包：349,449,525 字节，SHA-256 为 `b5e7a58bd634bd244e93440980ba3ff794e1f9c1e7ea148d6e0bc3f07f5b1c29`。
- 更新清单使用正式 Ed25519 密钥签名，并通过 1.2.2 已发布客户端公钥验证；公钥保持不变，私钥不进入源码或运行包。
- 干净构建的 8,042 个运行文件通过清单及哈希核对，标准 ZIP 不包含本地模型、账号数据、聊天缓存、API 配置或开发目录。
- 类型检查、404 项 Node 测试、11 组桌面脚本通过；Python 全套 411 项通过、3 项环境跳过，后续追加边界测试通过。启动端口修复另经原有 41 项启动器测试和 5 项备用端口测试验证。
- 包内 Python 及 Node 在仅系统 PATH 下通过依赖导入和 API worker 启动检查。由最终 ZIP 独立解压的标准包在原先命中系统保留端口的目录中完成可见界面就绪检查，并正常清理所属服务。

发布资产与实际运行过的验收副本分开保存，不会将运行后生成的数据重新压入 ZIP。上述检查不代替其他用户设备与显卡环境的实机验证。
